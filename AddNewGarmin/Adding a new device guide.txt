Store listing:
https://apps.garmin.com/en-US/apps/789012f0-dcb2-46c2-b5b8-ef00a75968fa?tid=2

Current machine: Fedora Linux 44 (Workstation), VS Code installed as a **Flatpak**.
Legacy Windows instructions are kept at the bottom for reference.

================================================================================
## 1. Adding a new device
================================================================================

1. Launch the SDK Manager (it needs its own compat libraries, so use the
   launch script, not the raw binary):

       ~/Projects/CameraClick/AddNewGarmin/connectiq-sdk-manager-linux/bin/sdkmanager-launch.sh

   Or use the "Connect IQ SDK Manager" desktop launcher.

2. Download the latest SDK if prompted.

3. Go to the **Device** tab and add the devices you want.
   Not everything listed is a watch — only grab the relevant ones.

4. Add the device to the manifest, either in the VS Code UI
   (Ctrl+Shift+P -> "Monkey C: Edit Products") or by editing directly:

       ~/Projects/CameraClick/Comm Watch/manifest.xml

   There is a Select All checkbox if you want every supported device.


================================================================================
## 2. Building
================================================================================

In VS Code:
   Ctrl+Shift+P -> "Monkey C: Build Current Project"  (or "Build for Device")
   Pick a device, wait for BUILD SUCCESSFUL.

Output lands in `Comm Watch/bin/CommWatch.prg` (gitignored).

Note: building only produces the .prg file. It does NOT open the simulator or
show you anything. To actually see the app run, see section 3.


================================================================================
## 3. Running in the simulator
================================================================================

IMPORTANT: the simulator must be started from a REAL HOST TERMINAL, not from
VS Code's integrated terminal. VS Code is a Flatpak, so its terminal runs in a
sandbox that is missing libraries the simulator needs. See the Sandbox section
in Troubleshooting — this cost hours once already.

How to tell which terminal you are in:
   caleb@pc-cs:~$     <- real host terminal (good)
   sh-5.3$            <- VS Code's sandboxed terminal (simulator will NOT start)

Steps:

1. Once per session, in a HOST terminal (GNOME Terminal, etc.):

       connectiq-sim

   The CIQ Simulator window opens. Leave it running.

2. Then either:

   a) In VS Code: Run and Debug panel (Ctrl+Shift+D) -> "Run App" -> F5.
      It connects to the already-running simulator over localhost. This works
      from inside the sandbox because Flatpak shares the host network.

   b) Or from any terminal:

       cd ~/Projects/CameraClick/Comm Watch
       monkeydo bin/CommWatch.prg fr265

Why the wrapper scripts exist:
   connectiq-sim  sets LD_LIBRARY_PATH to ~/.Garmin/compat-libs, because
                  Fedora 44 dropped the GNOME-3-era libraries the simulator
                  was built against.
   monkeydo       puts the JDK on PATH, because the SDK's own monkeydo calls a
                  bare `java` and fails otherwise.
Both auto-detect the newest SDK/JDK, so they survive SDK updates.


================================================================================
## 4. Exporting for the store
================================================================================

   Ctrl+Shift+P -> "Monkey C: Export Project"
   Choose the `Comm Watch` folder.

This builds for every device in the manifest and produces the .iq file to
upload. It signs with ~/.Garmin/developer_key.der — see the warning below.


================================================================================
## 5. THINGS YOU MUST NOT BREAK
================================================================================

>> The developer key
   ~/.Garmin/developer_key.der is the ORIGINAL key from the old Windows
   machine. The app is already published and signed with it. If it is lost or
   replaced with a freshly generated one, you can never publish an update to
   the existing store listing again.

   Known copies of the key:
   - Working copy: ~/.Garmin/developer_key.der  (what builds actually use)
   - Backup copy:  AddNewGarmin/developer_key.der
   - Old Windows computer (the machine it was originally generated on)
   The two local copies are chmod 600 and byte-identical.

   - Do NOT use "Monkey C: Generate a Developer Key" on this project.

   THIS REPO IS PUBLIC (github.com/Caleb-Seely/GarminRemoteV2), so the key
   must never be committed. .gitignore covers it via *.der, developer_key*,
   *.pem and *.key. Verify any time with:

       git check-ignore -v AddNewGarmin/developer_key.der

   Note the old rule `developer_key` alone did NOT match `developer_key.der`
   — exact-name patterns don't cover extensions. That gap is now closed.

   BEFORE WIPING OR DISPOSING OF THE OLD WINDOWS COMPUTER: that machine holds
   the third copy of this key, and it is the only one on separate hardware.
   Both Linux copies are on the same disk, so if that machine goes away, a
   single drive failure or OS reinstall could orphan the store listing.
   Move that copy to a password manager or external drive first.

>> The app UUID
   manifest.xml id="f4ac6a38-3843-4ae7-8bec-1b4f752b9d1f"
   Same deal — this identifies the published app. Never run
   "Monkey C: Regenerate UUID" on it.

## 6. Troubleshooting
================================================================================

--------------------------------------------------------------------------------
ERROR: Unable to load private key: undefined (No such file or directory)
   ...and the build command shows `-y undefined`
--------------------------------------------------------------------------------
The `monkeyC.developerKeyPath` setting is not being found.

THE GOTCHA: VS Code only reads .vscode/settings.json from the folder that is
open as the WORKSPACE ROOT. This repo can be opened two ways:

   ~/Projects/CameraClick              (parent, contains several projects)
   ~/Projects/CameraClick/Comm Watch   (just this project)

A settings.json in the parent does NOT apply if you opened only "Comm Watch".
The setting now exists in BOTH locations so either works:

   "monkeyC.developerKeyPath": "/home/caleb/.Garmin/developer_key.der"

After changing it, run Ctrl+Shift+P -> "Developer: Reload Window". The
extension caches the build task at startup and will keep passing the old value
until you reload.

--------------------------------------------------------------------------------
Simulator won't start — missing shared libraries
   libwebkit2gtk-4.0.so.37 / libsoup-2.4.so.1 / libxml2.so.2
   or: "No image loaders are configured ... glycin-loaders"
--------------------------------------------------------------------------------
FIRST: check you are in a host terminal, not VS Code's sandbox (see section 3).
Most of these errors only ever appear inside the Flatpak sandbox.

What the HOST has vs what the SANDBOX has:

   library                        host    sandbox
   libwebkit2gtk-4.0.so.37         yes      no
   libxml2.so.2                    yes      no
   glycin-loaders                  yes      no
   libsoup-2.4.so.1                 no      no   <- compat-libs supplies this
   libjavascriptcoregtk-4.0.so.18   no      no   <- compat-libs
   libjpeg.so.8                     no      no   <- compat-libs
   libicu*.so.70                    no      no   <- compat-libs

So: host terminal + compat-libs = works. That is exactly what `connectiq-sim`
does. If you ever need it by hand:

   LD_LIBRARY_PATH="$HOME/.Garmin/compat-libs" \
     ~/.Garmin/ConnectIQ/Sdks/connectiq-sdk-lin-<version>/bin/connectiq

Do not bother installing packages to fix these — glycin-loaders and libxml2
were already installed; the errors were purely a sandbox artifact.

--------------------------------------------------------------------------------
sh: monkeydo: command not found
--------------------------------------------------------------------------------
The SDK's bin folder is not on PATH. Use the `monkeydo` wrapper in
~/.local/bin (already handles this, plus the java-not-found problem below).

--------------------------------------------------------------------------------
monkeydo: line 72: java: command not found
--------------------------------------------------------------------------------
The SDK's monkeydo script calls a bare `java` and ignores the
`monkeyC.javaPath` VS Code setting. The wrapper prepends
~/.local/opt/jdk-*/bin to PATH. That VS Code setting only affects builds
started from within VS Code.

--------------------------------------------------------------------------------
Unable to connect to simulator.
--------------------------------------------------------------------------------
The simulator isn't running (or it crashed on startup). Start it with
`connectiq-sim` from a host terminal first, confirm the window is actually
open, then retry.

--------------------------------------------------------------------------------
Pressing F5 / "Run App" does nothing useful
--------------------------------------------------------------------------------
Check .vscode/launch.json exists in whichever folder you opened as the
workspace root. Config used:

   { "type": "monkeyc", "request": "launch", "name": "Run App",
     "stopAtLaunch": false, "device": "${command:GetTargetDevice}" }

Remember Flatpak VS Code can never LAUNCH the simulator itself — it can only
connect to one already running on the host.

## 7. Known build warnings (safe to ignore)
================================================================================

- "The launcher icon (48x48) isn't compatible with the specified launcher icon
  size of the device 'X' (40x40 / 60x60). The image will be scaled."
  Cosmetic. Fix properly by supplying per-device launcher icons if it ever
  looks bad on real hardware.

- "This is a 'watch-app' app type but no source code was annotated with
  (:glance). The entire application will be loaded as a glance process."
  Expected — this app has no glance view.

- "'Toybox.Communications.setMailboxListener' is deprecated"  (CommApp.mc:38)
  "'Toybox.Communications.emptyMailbox' is deprecated"        (CommApp.mc:87)
  Still functional. Worth migrating to the newer Communications API at some
  point, but not urgent.

If you ever see "Duplicate permission: Communications", there are two
<iq:uses-permission> entries in manifest.xml. There should be exactly one.


================================================================================
## 8. Future reference / worth checking
================================================================================

- Switching VS Code from Flatpak to the native RPM build would remove the
  "start the simulator manually first" step entirely — F5 would launch it
  directly. Worth doing if the two-step dance gets annoying.

- Nothing depends on ~/Downloads any more. The SDK Manager was moved into
  AddNewGarmin/, and these three references were updated to match:
     ~/.Garmin/ConnectIQ/sdkmanager-location.cfg
     ~/.local/share/applications/connectiq-sdk-manager.desktop
     (bin/sdkmanager-launch.sh uses relative paths, so it needed no change)
  If you ever relocate it again, update those same three things.

- The SDK Manager folder is 314MB and gitignored via
  /AddNewGarmin/connectiq-sdk-manager-linux. Do not remove that rule — a
  public repo does not want 314MB of .so files in its history.

- After any SDK update, just re-run `connectiq-sim` — the wrappers pick the
  newest SDK automatically. No PATH edits needed (unlike the old Windows
  setup).

- .vscode/ is gitignored, so developerKeyPath and launch.json do NOT travel
  with the repo. Neither do the ~/.local/bin wrappers or ~/.Garmin/compat-libs.
  On a new machine, recreate: the developer key, both settings.json entries,
  launch.json, the two wrapper scripts, and the compat-libs copy.

- Build artifacts (bin/, *.prg, *.iq) are all gitignored. Safe to delete
  ~/Projects/CameraClick/Comm Watch/bin at any time; the next build recreates
  it.

- Quick sanity check that a key is valid and is the right one:
      openssl pkey -in ~/.Garmin/developer_key.der -inform DER -noout -check
